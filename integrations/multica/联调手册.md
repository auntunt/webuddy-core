# WeBuddy × Multica 联调手册

将 WeBuddy 验收内核集成到 Multica 工作流的五步指南。

## 1. 安装 hook

在项目根目录安装 git hook，使 WeBuddy 能追踪代码变更：

```bash
webuddy hook install
```

**说明**: hook 兼容 Claude Code/Codex payload 语义（参照 ref/hook.js）。安装后 `.git/hooks/post-commit` 会向 `.webuddy/events.jsonl` 写入事件。

## 2. 打包 skill

将 `webuddy-acceptance` 技能打包为 `.skill` 文件（实质是 zip）：

```bash
cd integrations/multica
zip -r webuddy-acceptance.skill webuddy-acceptance/
```

## 3. 导入到 Multica

使用 Multica CLI 导入技能包：

```bash
multica skill import --file webuddy-acceptance.skill
```

**验证**: 执行 `multica skill list` 应能看到 `webuddy-acceptance`。

## 4. 绑定到 agent

为特定 agent 启用该技能：

```bash
multica agent skill bind <agent-name> webuddy-acceptance
```

或在 agent 配置文件中添加：

```yaml
skills:
  - webuddy-acceptance
```

## 5. 验证集成

触发一条 issue 任务，检查以下验证点：

1. **运行时加载**: 任务工作区应出现 `.claude/skills/webuddy-acceptance/SKILL.md`（Claude 运行时会展开技能）
2. **执行验证**: agent 完成任务后，issue 评论区应出现 WeBuddy 验收报告
3. **元数据写入**: issue metadata 应包含 `webuddy_verdict` 字段（值为 `pass`/`fail`/`blocked`/`needs-human`）

## 适用边界（§6.3）

**文件级认领锁的有效范围**:

- ✓ **同一 checkout 多会话**: 认领锁 (`claims.json`) 防止多个 Claude 会话同时修改同一文件
- ✗ **Multica 多任务场景**: 每个 Multica 任务是隔离的 git worktree，`.webuddy/` 不共享，认领锁不跨任务生效

**仍然有效的机制**:
- 轮次快照与反作弊（单任务内完整有效）
- 门禁判定逻辑（与并发控制无关）
- 人工确认记录（写入各自 worktree 的 records.jsonl）

**建议**: Multica 场景依赖 issue 级别的任务编排避免冲突，而非文件级锁。WeBuddy 在单任务内保证快照完整性和判定准确性。
